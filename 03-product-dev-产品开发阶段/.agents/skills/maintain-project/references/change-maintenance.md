# 变更与文件维护

## 按最高受影响范围定位

| 本轮变化 | 按职责定位的现有文件 | 不自动扩展的范围 |
| --- | --- | --- |
| 产品目标、范围或验收 | 当前需求与验收约定，以及受影响的设计或功能说明 | 不重写无关需求 |
| 跨功能的共享行为或数据含义 | 共享设计或接口约定，以及直接受影响的功能说明 | 不因名称相似修改独立功能 |
| 局部功能、页面或操作行为 | 对应设计、功能说明或接口约定；使用方式改变时同步使用说明 | 不强制重跑整个文档链 |
| 原型反馈与体验调整 | 已有原型设计、对应源码和验看记录；按影响判断需求看板与使用说明 | 不把演示方案、模拟规则或待讨论反馈升级为正式业务批准 |
| 行为不变的修复或实现调整 | 确有变化的实现说明或现有任务记录，以及实际验证记录 | 不为让检查通过而触碰未受影响的需求、设计或业务约定 |

实际文件职责由项目约定决定。找不到某类文档时，先查已存在的等价文件；本轮需要新的行为说明而确无承载位置时，创建一份最小记录即可，不制造平行事实源。

项目已采用 PRD、总 Spec、Feature Map、Feature Spec、Plan / Tasks 等结构时，按其既有层级和归属同步受影响内容。这些是可适配的项目合同，不是调用本 Skill 的前提；没有这套结构的项目不据此补建。

## 当前约定与历史过程

- 当前设计、需求和规格原位更新。已有编号继续使用；删除或替换行为有明确范围，相关入口和迁移影响一并处理。
- 原始需求与客户原件只读。把新输入写入当前设计、规格或已有修订区，并注明“本轮用户要求”“测试假设”等实际来源。
- 同一份计划和任务继续记录进度、偏差、未完成项和证据位置。已完成任务不抹除；后续新增工作使用新任务，行为变化时修订当前规格并说明旧证据的适用范围。
- 验证记录包含检查对象、实际命令或操作、结果和未验证项。不能以修改时间、文件被触碰或输出里出现 PASS 代替实际行为证据。
- AGENTS 保存项目入口和长期规则，Skill 保存可复用流程；每轮业务进度不写成新的全局规定。

## 接手与证据复用

明确项目和本次功能 → 读取当前相关文件 → 对照实际源码与已有结果 → 从未完成项继续。

运行记录只辅助本轮检查，删除后仍能依靠项目文档接手。代码、相关配置、检查脚本或输入改变时，只让依赖它们的旧证据失效；不能复用过期结果，也不为安心重复执行未受影响的检查。

## 不同项目的适配示例

- **原型反馈**：更新相关体验设计与同一个演示工程，验看受影响的操作；需求背景与看板是否变化单独判断，待讨论反馈保留确认状态。
- **接口变更**：更新对应实现、已有接口约定及直接受影响的调用方说明，用实际请求、响应与相关调用验证。
- **命令行工具或处理脚本**：更新相应实现，按影响同步参数、输入输出或使用说明，用代表性输入验证结果与退出状态。

这些是文件职责与验证方法的说明，不是固定文件清单，也不表示所有场景都已实测。使用当前项目已有的路径和有效约定，验收围绕本轮可观察行为、相关文档和实际证据。
