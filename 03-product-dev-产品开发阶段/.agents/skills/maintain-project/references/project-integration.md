# 为已有项目接入维护机制

只在用户要求建立或调整本项目协作机制时执行。日常需求迭代直接使用主流程，不每轮重新配置。

## 先确定实际入口

读取现有 AGENTS、源码与文档职责、可用检查命令及已有 Hooks；沿用当前路径，明确工作区根与各应用的源码入口。不要通过修改其他项目构建或原型生成 Skills 来接入本流程。

项目里的独立 Skill 安装位置是 `.agents/skills/maintain-project/`。使用已存在的安装副本；没有时按本次授权复制完整 Skill，避免只引用另一个人的机器绝对路径。项目级接入不修改全局配置。

## 补充 AGENTS

补充一个简短、项目特定的“已有项目维护”段落，内容包括：

1. 该项目实际的源码、当前设计/规格、验证记录和启动说明入口。
2. 新需求在同一个项目内落实，按影响同步相关文档；区分已确认约定、本轮要求和待讨论假设。
3. 使用 `$maintain-project` 承接这类迭代，检查命令来自真实工程。
4. 新路径、直接受影响旧路径及文档语义完成核对后才能报告完成。

已有相同约定时最小化合并。若采用受管理标记，只更新唯一且完整的一对标记内的内容；缺失、重复或顺序错误时停止该部分写入并报告冲突，不能截断标记外正文。无须把整份 Skill、每轮进度或通用规则复制进 AGENTS。

## 接入 Hook

本 Skill 自带处理脚本与接入示例，主流程可直接调用脚本检查。自动触发是额外的宿主接入：Codex 发出 `Stop` 事件，配置中的命令调用 `maintenance.py hook`，再由同一脚本检查当前会话仍活动的变更。

只有实际需要确定性结束检查时才新增项目 `.codex/hooks.json` 的一个 `Stop` handler：

```json
{
  "hooks": {
    "Stop": [{"hooks": [{
      "type": "command",
      "command": "python3 /absolute/project/.agents/skills/maintain-project/scripts/maintenance.py hook --project /absolute/project",
      "timeout": 10,
      "statusMessage": "检查本轮项目维护结果"
    }]}]
  }
}
```

真实生成时使用 shell 正确引用每个路径；示例中的绝对路径须替换为本机实际安装位置，项目迁移后重新生成该入口。脚本只依赖 Python 标准库。

合并已有 Hooks，保留其他 handler；按完整命令识别本 Skill 已有的 handler，避免重复注册。多个 Hooks 来源会同时运行，不能假设项目配置覆盖其他来源。先验证同一套检查脚本，再验证事件输入与会话绑定。

原生 Hooks 需要宿主实际加载和用户信任；安装或写配置不等于已生效，不绕过信任流程。项目接入输出应分别列出“文件已配置”“脚本已验证”“原生事件已验证/未验证”。

## 更新与移除

仅更新本 Skill 的约定段落、其 handler 和配套脚本，不重写其他工作流。变更协议或脚本后，验证受影响的实际样例；不自动重跑所有项目。移除时删去明确属于本 Skill 的接入项，保留业务源码、当前文档和正式验证记录；临时 `.codex/maintenance/` 仅在无活动变更且所需唯一证据已转存后清理。
