# 原型实现方式与技术栈选择

先形成需求、功能与页面的整体设计，明确相关信息和结果如何共同呈现，再选择实现方式与组件。多页面 HTML 也应共用业务对象、数据与状态含义，不为每条场景各建独立应用。一个业务名称不意味着必须生成后台管理系统；使用某个组件库也不意味着必须采用其常见的侧栏、统计卡片、表格和表单组合。用户参考和本轮呈现意图优先。

## 默认选择及适用条件

| 场景 | 选择 | 原因与约束 |
| --- | --- | --- |
| 新建，以页面浏览、步骤切换、筛选、弹窗和预置结果展示为主 | 多页面 HTML + 共享 CSS + 必要的原生 JavaScript | 默认路线；单页场景不强行拆页，不需要 npm 或构建步骤 |
| 原生页面需要更方便的开发预览、模块依赖或资源构建 | 在 HTML/JavaScript 上按需使用 Vite | Vite 支持原生 JavaScript 与多个 HTML 入口，不因此引入 React |
| 选定体验涉及大量相互影响的状态、复杂编辑或拖拽等交互 | 根据具体需要选择 React 等框架，再按需选择组件库 | 说明它比原生实现节省什么工作；不因“企业系统”或存在表格就默认上框架 |
| 已有应用或原型 | 沿用当前实现方式、框架和组件库 | 保留既有入口、主题和状态；本技能不因新默认触发迁移 |

这是演示载体的取舍，不是正式产品的技术选型。用户指定的实现方式优先，不为后续可能复用代码而提前搭完整工程，也不为了发挥工具能力扩大范围。各路线都遵守 `docs/04_frontend-prototype/` 目录约定。

各路线都先按 [应用产品设计方法](product-design.md) 确定页面空间、记录浏览和操作承接。分页、筛选、排序、必要的局部滚动与返回上下文不专属于组件库；采用原生 HTML 时也应实现本轮已经选定的体验，可用前端数组和少量会话状态完成。

## 默认 HTML 路线

- 按未来体验决定页面职责。真正的页面切换用相对链接，弹窗、抽屉、展开内容和结果更新用必要的页面内交互；不把业务场景拆成演示幻灯片。
- 用共享 CSS 统一颜色、字号、间距和反馈，模拟数据集中维护。页面数量较多时按实际重复内容复用结构，不预先搭通用组件平台。
- 跨页只携带本轮需要的对象、选择和工作上下文，如筛选、排序与页码；URL 参数能表达时直接使用，确需会话状态时再用 `sessionStorage`，并提供重置。返回列表时按设计恢复必要位置，不因页面重新加载而丢失原工作。不要为了维持一次演示引入业务数据库或完整状态库。
- 用本地静态 HTTP 服务预览；读取外部 JSON 或使用 JavaScript 模块时，不以双击 `file://` 作为默认运行方式。启动方法写入原型 README，优先复用已有工具。
- 多页面需要留意共用结构和跨页状态的一致性；如果这些维护工作已明显超过框架成本，再说明证据并调整实现方式。

## 确需框架时的组件选择

采用框架仍然只实现演示所需的交互，不要求正式业务引擎。没有必要在首次使用 Skill 时预先安装下列组件库。

### shadcn/ui

- 它是把组件源码加入工程的工具与组件体系，不是要另外部署的服务。
- CLI 新建工程可选择底层组件实现。[安装说明](../INSTALL.md)保留的可选示例固定 Radix；已有工程依 `components.json` 与实际源码选择。
- 只添加页面需要的组件。例如 `button`、`dialog`、`input`、`table`、`select`、`sheet`；组件名和 API 以当前版本官方文档为准。
- `table` 不会自动带出业务筛选、分页或排序。简单演示可用前端数组派生；需要复杂数据表能力时再依官方 Data Table 指南组合表格库。
- 调整语义化颜色变量与组件组合，避免每页各写一套视觉规则。
- 不凭旧例子假定 `asChild`、受控属性或表格 API 在所有底层实现和版本都相同。

### Ant Design

- 直接在 React 工程安装 `antd`，按需使用组件，不需要单独部署 UI 服务。
- 选定体验确实依赖复杂表格、表单等现成能力时再考虑，按设计记录配置主题和布局；只有几张表或几个输入框不构成引入理由。
- 不为搭建少量原型页面默认引入整套 Ant Design Pro 或后端框架。

## 按需求增加依赖

- 路由：HTML 页面本身有地址和浏览器前进/返回，无需为此加路由库；框架方案按实际页面定位需求选择。
- 状态：先用预置内容和必要的前端状态；采用 React 时可用 state/context，不为模拟真实系统建立完整状态管理体系。
- 表格、图表、拖拽和动效库：页面实际需要再加入。Emil 心法不等于必须安装某个动画包。
- 默认不需要 Next.js、数据库、服务端 API、Figma、v0、付费模型 API 或 MCP。
