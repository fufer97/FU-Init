# 背景资料格式

这套格式是本技能为可检索、可追溯而采用的项目约定，不是 OpenAI 强制的文档标准。保持简体中文单一正文，技术标识和原始文件名按原文保留。

## 输出组织

- 默认在 `docs/01_normalize-project-requirements/` 下统一组织客户需求、业务约定和沟通记录。用户指定其他名称时沿用指定名称，三类资料仍放在同一个父目录内，不与后续阶段文档混放。
- 一份纳入范围的来源文档对应一份规范化 Markdown，按资料性质放入对应子目录。没有来源的类别不预建空目录；原始目录没有分类时，在输出中按资料性质归类，不移动来源文件。
- `index.md` 是入口，包含简短使用说明、文档清单，以及确实存在的未确认、冲突或未处理事项。
- 将已读取的业务事实、约定、理由和适用条件写入规范化正文。原始链接用于追溯，不能用文件标题或网址代替内容；只有链接、尚未取得正文的资料在索引中标为未读取，不计为已整理。
- 需求资料引用的图像、音视频、业务表格等附件只保留来源链接及原文已有说明，不为附件另建规范化文档，不读取其业务数据或解读素材，也不提前编制功能 Spec。扫描形式的需求书或沟通记录本身属于需求资料，按实际内容判断，不按扩展名一律排除。

默认目录结构：

```text
docs/
└── 01_normalize-project-requirements/
    ├── index.md
    ├── 客户需求/
    ├── 业务约定/
    └── 沟通记录/
```

目录改名或迁移时同步项目 `AGENTS.md` 和相关链接，保留文档编号与条目锚点。

## 文档元数据

使用 YAML frontmatter；以下占位符仅用于说明，交付时填写有依据的实际值。

```yaml
---
id: REQ-001
type: 客户需求
source: "相对于当前文档的原始文件路径"
source_sha256: "原始文件内容的 SHA-256"
source_date: "原文明确记载的日期；没有则为 null"
participants: ["原文明示的相关人员；未知则为空列表"]
topics: ["能够帮助当前讨论检索的少量主题词"]
status: "按来源或用户确认填写；未知写未标注"
---
```

- 优先复用来源中的稳定编号；没有时分配简短编号，并在后续更新时保持不变。
- `source_date` 取记录日期，不使用文件修改时间冒充业务日期。日期有矛盾时保留原文值并标明问题。
- 文档被确认为项目资料，不代表里面每个业务事项都已批准。原文中的待确认、尚未放行、申请中等状态必须保留。
- `source_sha256` 用于识别后续来源变化，不表示资料已经通过业务验收。
- 输出文件的链接使用相对路径，路径含空格时按 Markdown 规则处理。

## 正文与条目

正文先用一句话说明资料主题，并链接原始文件。之后按业务含义分节，保留原本的问答、限定条件和分歧。每节使用稳定标识，例如 `REQ-001-01`；需要跨文档链接时添加对应的小写 HTML 锚点。

```markdown
<a id="req-001-01"></a>
## REQ-001-01 业务问题

来源定位：原始文件第 8–12 行。

忠实整理的内容……
```

定位按文件类型选择：文本行号、PDF 页码、工作表及单元格、访谈章节、音视频时间段。只写确实读取到的定位；无法取得精确位置时说明可用的章节或记录标识，不编造页码和行号。

按内容性质组织，而不改变性质：

- 客户诉求：现状、痛点、期望、范围、验收方向和待确认项。
- 业务约定：适用对象、条件、规则、权限及明确存在的例外。
- 沟通记录：时间、参与人、问题与回答、明确决定和未完成事项。个人观点保留归属，不提升为双方决定。
- 历史决定：选择、理由、适用前提及后续替代关系；只有来源明确说明时才标注被替代。

不要强制为每份文件填满所有章节。来源没有的内容不创建空模板。整理者发现的问题单独标为“整理发现”，不可混进来源原话。

## 索引内容

每条至少包含：文档编号、文件链接、资料类型、覆盖主题、适合回查的问题。索引提供发现线索，不替代正文证据。

索引开头说明本次需求资料的来源范围。范围内每份需求文档必须可核对：已整理文档列入清单，无法处理的需求文档说明原因及路径，不能因格式不同无声跳过。来源目录中的其他业务文件不属于这份清单；正文引用的附件保留原始链接即可，不计为已整理需求文档。

索引末尾可简要记录实际发现的问题，例如时间冲突、未量化的验收方向、缺失的附件。不能为了凑问题清单推测不存在的风险。

## 核对

逐份对照来源，重点检查数量、金额、时间、对象范围、否定词、审批责任和未确认事项。来源没有明确优先级时，不凭文件更新日期自动消解冲突。

检查本地链接和稳定锚点，确认后续讨论能从引用回到原始位置。原文件有变更时，更新对应整理版、来源定位与索引，避免保留两个相互矛盾的“当前版本”。
