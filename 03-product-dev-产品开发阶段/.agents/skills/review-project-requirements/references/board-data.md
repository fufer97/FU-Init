# 三列看板数据格式

`board-data.json` 保存业务内容及生成时的来源依据，`assets/board.html` 与 `assets/board-row.html` 保存已确认的浅色三列版式。默认输出包含阅读调节，不展示来源目录，也不包含评论或提示词复制。条目多少由材料决定，长内容自然撑高卡片。

## 项目与行内容

- `schema_version`：当前为 `1`。
- `reading_controls`：可选布尔值，默认 `true`。提供标准／稍大／大字、舒展／紧凑及恢复默认控件。用户明确需要静态版本时可设为 `false`。
- `project.title`：页面品牌行中的客户或项目名称。
- `project.badge`：可选的简短范围标签，默认“范围”；如“F01”或“一期”。
- `project.scope`：简短的本轮范围，显示在标题下方。
- `project.boundary`：需要保留的主要业务边界，显示在页脚。
- `project.effect_note`：效果指标的确认情况。区分预期与已验证成效，不填虚构的量化目标。
- `rows`：按业务阅读顺序排列的关联行。每行包含以下字段。

| 字段 | 用途 |
| --- | --- |
| `id` | 唯一、稳定的行编号，用于维护，不作为业务编号展示 |
| `pain.title` / `pain.description` | 客户遇到的困难及其具体表现，不写成技术方案 |
| `feature.title` / `feature.actions` | 拟做功能名称及简短动作列表，通常一到三条即可 |
| `effect.title` / `effect.description` | 预期业务结果及补充说明，不重复功能清单、不假定已经实现 |
| `references` | 该行的来源定位数组，每项包含 `source` 与 `location` |

一行是一组明确的“痛点—功能—效果”关系。一个痛点需要几个独立功能时可分行说明，保持痛点名称一致；一个功能服务多个痛点时，说明它对各痛点的不同作用。不为减少行数合并无关问题。

行编号、配色和装饰图标由模板按阅读顺序生成，不携带业务状态含义。客户内容不写进素材或模板；无需为了匹配图标编造条目。

## 来源依据

`sources` 只列实际使用的文档，每项包含：

- `id`：数据内唯一的来源标识。
- `path`：相对于 `board-data.json` 的文件路径。
- `sha256`：该文件当前字节内容的 SHA-256。

`references[].source` 对应来源标识，`location` 写真实存在的条目编号、章节、页码或段落。已有规范化编号时直接复用；不要仅写“见文档”。未规范化文件也可作为来源，但必须先实际读取相关内容。

生成器会检查文件是否存在、内容是否变化以及来源标识是否有效；不判断定位的语义是否正确，也不证明某一段支持某个结论。这两点应在内容提炼时完成。不要为了让脚本通过而只刷新校验值、跳过复核。

## 最小示例

下面是结构示例，业务内容、路径、定位和校验值在使用时都需要替换，不作为事实或可直接运行的输入：

```json
{
  "schema_version": 1,
  "project": {
    "title": "某项目 · 需求梳理",
    "scope": "本轮讨论范围",
    "boundary": "涉及业务决定时由相应负责人确认。",
    "effect_note": "以下为预期效果，量化指标待核实现状后确定。"
  },
  "sources": [
    {"id": "SOURCE-01", "path": "../项目需求.md", "sha256": "填写真实的64位SHA-256"}
  ],
  "rows": [
    {
      "id": "pain-1",
      "pain": {"title": "事情交出去了，结果跟不住", "description": "无法明确知道是否有人接手以及当前阻碍。"},
      "feature": {"title": "任务进展跟踪", "actions": ["记录负责人、是否接手、当前进展和结果。"]},
      "effect": {"title": "未完成事项找得到人、看得到进展。", "description": "降低跟进遗漏，区分已经通知和实际完成。"},
      "references": [{"source": "SOURCE-01", "location": "需求文档中的实际章节或条目"}]
    }
  ]
}
```

生成命令见 `SKILL.md`。输出 HTML 与数据放在同一目录；生成后的 HTML 可以离线打开，来源文件路径与校验值仅用于生成核对，不嵌入页面浏览功能。
