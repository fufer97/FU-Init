# 对话示例与范围判断

以下为虚构的小例子，只示范讨论节奏，不能套用为项目事实或固定分类体系。实际使用时先读真实资料，再决定该问什么。

## 已读材料，带着建议提问

已读到一份采购明细 CSV、一封供应商交期回复邮件和一份分批交付说明 PDF。三份材料的内容都围绕采购与供应商交期。

可以这样说：

> 这三份资料分别记录采购明细、供应商回复和分批安排。我建议先归为“采购与供应交期”，保留三个文件各自的格式和内容。这样能从业务口径找到资料，也便于之后分别选择读取方法。
>
> 这一组先合在一个业务类别里，还是需要把“采购订单”和“供应商交期”分开？我建议先合在一起，当前分类更简单。

到这里等待回答，不接着替用户选择，也不开始创建分类目录。

若用户回答“分开，订单给采购看，交期给计划看”，先核对哪些内容确实分别承担这两个用途，再更新类别。后续发现一份 PDF 同时涵盖二者时，只围绕该文件的归属提出下一问，不重新询问已经确定的两个类别名称。

## 能查到的事实，不变成问卷

- 已列出目录和文件类型，就不再问用户“有哪些格式”。
- 分类取决于 PDF 的实际内容时，先读取 PDF；不能只凭文件名追问用户它属于哪里。
- 只读了表头与少量记录，就说明这是样读；类型或业务含义仍不清楚时再定向读取。
- 用户已经给出业务目标时，直接据此提出类别建议，不让用户从零设计分类树。

## 确认与执行

| 情况 | 下一步 |
| --- | --- |
| 用户说“这个类别名可以”，其他类别与文件归属仍未确定 | 记录这一项决定，继续必要的讨论 |
| 已呈现完整清单、类别、动作和输出位置，用户说“就按这个方案整理” | 开始构建已确认结果，不再询问同一授权 |
| 用户说“先给我看看建议，别整理” | 读取材料并展示分类草案，保持在讨论阶段 |
| 用户要求“执行上次确认的方案”，当前上下文已有该方案和有效授权 | 对照范围后直接执行，缺失的关键上下文才需要回查或补问 |
| 一个文件无法读取，其他文件已清楚 | 记录该文件的限制，推进不依赖它的讨论与整理 |
| 文件暂时不知归哪一类，用户要求先放着 | 单列暂缓项，不猜一个类别填上 |
| 用户仅批准生成分类索引 | 生成索引并保留原始路径，不把文件移入新目录 |

## 收敛

每轮讨论一个会改变分类结果的决定即可，不预设必须问多少轮。分类定义、清单归属、读取限制和构建动作已清楚时，提交当前方案供审核，不继续拓展到数据平台或架构问题。
