# 05-核心对象与编码操作规范

## 一、核心业务对象分层（按项目实际裁剪）

> 若项目存在「计划/申请 → 实际执行 → 结算/归档」类多阶段流转，在此明确各层职责与边界，防止概念混用。

| 层级 / 环节 | 名称 | 核心职责 | 典型对象举例 |
|---|---|---|---|
| 第 1 层 | 【意图 / 计划层】 | 记录计划与约定，审核前可编辑，审核后关键字段锁定 | 【待确认】 |
| 第 2 层 | 【实际执行层】 | 记录真实发生的动作，驱动核心台账/状态变化 | 【待确认】 |
| 独立环节 | 【结算 / 复核环节】 | 挂接在执行结果之上，独立记录或核销 | 【待确认】 |

**核心架构规则**：
- 【待确认】执行层记录是否必须关联前置计划层？
- 【待确认】哪些动作会真正触发核心数据/库存/余额变动？
- 【待确认】确认/审核后哪些关键字段锁定不可修改？

## 二、业务编号与编码规则

### 编号前缀表

| 业务对象 / 单据类型 | 前缀 | 格式 | 示例 |
|---|---|---|---|
| 【对象 A】 | `XX` | `{前缀}{YYYYMMDD}-{4位序号}` | `XX20260101-0001` |
| 【对象 B】 | `YY` | `{前缀}{YYYYMMDD}-{4位序号}` | `YY20260101-0001` |
| 【系统流水】 | `FL` | `FL{YYYYMMDD}-{8位序号}` | `FL20260101-00000001` |

### 通用编码约束

- 序号按日（或按月）递增，同周期同类型内唯一不重复。
- 单据/记录确认生效后，编号不可修改。
- 取消或作废的编号不回收复用，保证追溯连续性。

## 三、通用操作动词规范（全局按钮与文案统一）

| 规范用词 | 含义 | 禁止混用 |
|---|---|---|
| 新增 | 创建新主数据或新业务记录 | 新建、创建、添加 |
| 编辑 | 修改已有记录 | 修改、更新、变更 |
| 查看 | 进入详情页只读展示 | 详情、预览 |
| 停用 | 终止主数据可被新记录引用 | 禁用、冻结、下架 |
| 启用 | 恢复主数据可被新记录引用 | 激活、解冻、上架 |
| 取消 | 撤回未产生下游执行的记录 | 作废（除非明确区分状态语义） |
| 搜索 | 提交筛选条件 | 查询（作为按钮文案时禁用） |
| 导出 | 导出当前列表或筛选结果 | 下载、导出 Excel |

## 四、主数据通用规则

- 核心主数据（基础档案）**默认不提供物理删除能力**，统一通过「停用」处理。
- 停用后不可在新建业务记录时被选中，但历史记录仍完整保留原引用与快照。
- 新增主数据默认状态为「启用」，新增表单不展示状态选择项。
