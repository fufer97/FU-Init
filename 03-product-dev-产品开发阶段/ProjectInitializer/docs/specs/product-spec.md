## 3. 产品对象与职责

| 对象 | 用户可感知含义 | 身份与关系 | 负责 | 不负责 | 相关 PSC |
|---|---|---|---|---|---|
| `ProjectInitConfig` | 当前项目初始化的全局参数配方 | 全局唯一根状态，驱动所有阶段与模板渲染 | 维护预设 ID、语言、主力 Agent、所选阶段、开发模式及可选项目元信息 | 不直接保存渲染后的静态文件字符串 | PSC-001, PSC-002 |
| `StageBlueprint` | `01`～`05` 五个软件工程阶段的定义与目录树 | 由 `stageId`（`'01'..'05'`）唯一标识，隶属 `ProjectInitConfig` | 承载该阶段的固定编号、多语言名称及 2/3 级 `TreeNode` 层次结构 | 不跨阶段混放其他岗位的文件 | PSC-001, PSC-003 |
| `TreeNode` | 阶段工作区内的单个文件夹或文件节点 | 树内 `id` 唯一，具有明确 `level`（`2` 或 `3+`）与 `numbered` 属性 | 决定勾选状态、同级排序位置、自定义名称及关联模板 | 不在 UI 勾选树中暴露自动生成的 3 级 `README.md` 与 `.gitkeep` | PSC-001, PSC-003, PSC-004 |
| `ResolvedArtifactBundle` | 实时计算出的最终导出文件清单（路径 → 文本内容） | 由 `ProjectInitConfig` + `TreeNode` 纯函数派生 | 同时供给右侧「目录树/文件全文预览」、JSZip 打包器与沙箱 Shell 脚本生成器 | 不包含未勾选阶段或未勾选节点 | PSC-004, PSC-006, PSC-007 |

## 4. 全局状态与生命周期

### 状态模型

```text
[01 方案图册页 (atlas)] ──(点击 W01/W02/W03 卡片或自由配置)──> [02 全局配置页 (config)]
        │                                                            │
        └────────(点击卡片“直达目录工作台”)──────────────────────────┴──> [03 树形工作台与导出页 (workbench)]
                                                                                  │
                                                                    (点击“打包下载初始化 ZIP”)
                                                                                  ▼
                                                                  [交付弹窗：ZIP 下载 + Agent 口令 + 沙箱脚本]
```

- [PSC-002] 当用户在任意入口修改 `selectedStages` 时：
  - 若 `selectedStages` 同时包含 `'02'` 与 `'03'`，且 `devModeOverride === false`，`devMode` 必须自动切换为 `'linked'`（精简开发模式，挂载 6 个改造后核心技能，跳过 `docs/PRD.md`）；
  - 若 `selectedStages` 包含 `'03'` 但不包含 `'02'`，且 `devModeOverride === false`，`devMode` 自动切换为 `'full'`（完整开发模式，挂载 12 个通用软件工程技能）；
  - 当用户显式开启手动开关（`devModeOverride === true`）时，允许在单选 `'03'` 时强制保持 `'linked'` 模式，以便为已有设计稿的项目增量补建开发阶段。
- [PSC-005] 在 `01 方案图册页` 点击 `W01..W03` 任一方案卡片，必须原子更新 `presetId`、`selectedStages`、`devMode` 与默认目录勾选树，不存在半更新状态。

## 5. 跨 Feature 不变量与共享行为

- [PSC-001] 用户在 `02 全局配置页` 填写的可选项目元信息（`projectName`、`projectSlug`、`projectSummary`、`techStack`）必须作为单一事实源，同时注入 `02-产品设计阶段`（`AGENTS.md`、`01-项目背景.md`）与 `03-产品开发阶段`（`AGENTS.md`、`.agents/skills/build-fde-project` 示例命令）及顶层 `项目启动.md`；留空字段统一渲染为清晰的 `【待补充：...】` 占位符。
- [PSC-003] 目录命名与重排不变量：
  - 1 级阶段文件夹固定使用 `01`～`05` 两位编号前缀；
  - 2 级及以下 `numbered: true` 的已勾选普通业务文件夹，在同一父目录下严格从 `1` 开始连续编号（`1-`、`2-`、`3-`），绝不出现跳号、`1.1-` 或断号；
  - `numbered: false` 的系统与工程约定节点（`.agents`、`rules`、`skills`、`.antigravityignore`、`AGENTS.md`、`README.md`、`Raw`、`HANDOFF.md`、`项目启动.md`）在 `zh`、`en`、`bilingual` 任何语言下均保持原名且不加序号；
  - `bilingual` 模式统一采用「英文在前、连字符连接」（如 `1-context-业务上下文`）。
- [PSC-004] 自动文件注入不变量：
  - 树形勾选器 UI 永远隐藏 3 级及以下自动生成的 `README.md` 与 2 级空目录 `.gitkeep`；
  - 在生成的 `ResolvedArtifactBundle` 中，每个 `level >= 3` 的已勾选文件夹必须自动拥有一份列出其子项职责的 `README.md`；每个 `level == 2` 的无子文件已勾选文件夹必须自动包含 `.gitkeep`；2 级文件夹自身不自动生成 `README.md`（由 1 级阶段 `AGENTS.md` 的二级目录表动态索引）。

## 7. 安全、权限、失败与恢复

- [PSC-007] 顶层 `项目启动.md` 必须包含明确的「初始化完成后自清理指令」（提示或由本地 Agent 将 `项目启动.md` 归档至 `drafts/` 或删除），防止后续对话重复误触发初始化。
- [PSC-008] 隐私与沙箱安全：
  - 全程在浏览器本地内存执行，不向任何外部服务器发送用户填写的项目名称、背景或配置数据；
  - `localStorage` 配置持久化与 JSON 导入解析均包裹 `try/catch`：在严格沙箱禁用 `localStorage` 时自动退化为内存态而不白屏报错；导入非法 JSON 时给出明确中文错误提示并保留原状态（`EX-03`）。

## 8. 兼容、能力与产品语言

- [PSC-005] 界面全面遵循 Oil UI `#atlas` 画册编辑美学与 `unslop` 规范：
  - 色彩固定采用暖纸色阶（`#FAF9F6` 背景、`#17201B` 深墨主字、`#5B615C` 次级字、`#E6EBE4` 鼠尾草绿胶囊、`#E2E1DC` 1px 细线），严禁紫色/霓虹渐变、发光阴影与标题 Emoji；
  - 字体层级由修长衬线标题（`Instrument Serif / Songti SC / Noto Serif SC`）、等宽编号（`W01`、`01`）与干净无衬线正文构成。
- [PSC-008] 构建产物兼容性：通过 `vite-plugin-singlefile` 将所有脚本、样式、图标与 12 个通用软件工程 Skills 模板内联至单个 `dist/index.html`，无任何外部 CDN 依赖，可直接上传 WorkBuddy 资料库发布为网站。

- 共享的 `ProjectInitConfig` 状态机与 `ResolvedArtifactBundle` 计算引擎不得在多个组件中各自复制实现。
