# 一键项目初始化核心模块 — 业务 PRD

> **所属阶段**：`02-product-design-产品设计阶段`
> **关联上下文**：`1-context-业务上下文/` 全部规范文件
> **权威字段源**：`项目初始化配置字段清单.md`
> **状态**：已确认（Confirmed）

---

## 1. 需求背景与业务目标
- **业务痛点**：AI 时代启动软件工程项目时，产品设计的上下文目录（`context/template/prd`）与开发交付的 FDE 工程体系（`Raw/.agents/skills/<Project>`）彼此割裂；手动创建目录、按语言改名、重排编号、裁剪 Skills 并清理特定品牌/个人硬编码极其耗时且易出错。
- **本期目标**：提供一个纯前端运行、零 LLM 调用成本、符合 Oil UI `#atlas` 画册编辑美学的单文件 HTML Web 配置器（可直接发布至 WorkBuddy 资料库），支持用户通过 3 步完成五阶段目录、上下文模板与双模式开发 Skills 的可视化定制与 ZIP 一键导出。

## 2. 范围与边界（In Scope / Not In Scope）
- **本期包含（In Scope）**：
  1. **画册级方案图录页（第 1 页）**：展示 3 套核心预设方案（`W01 产品设计专精`、`W02 设计→开发联动全流程`、`W03 完整 FDE 开发交付`），支持分类胶囊筛选与一键带入配置。
  2. **全局配置与双模式联动引擎（第 2 页）**：支持三语言（中文 / 英文 / 中英双语）、主力 Agent（Antigravity 2.0 / 通用标准 Agent）、五阶段选择、开发阶段「完整模式（12 技能）vs 精简模式（6 技能）」自动判定与手动切换、可选项目元信息（项目名、英文工程名、简介、技术栈）及 JSON 配置导入/导出。
  3. **树形轻编辑与实时文件内容预览工作台（第 3 页）**：支持节点勾选、同级上下调序（动态重算 `1-`、`2-` 序号）、新增/重命名自定义节点，右侧实时预览完整目录树与任意文件的渲染后正文。
  4. **ZIP 本地生成与最后一公里接管闭环**：浏览器内联 JSZip 生成顶层不含 0 级项目文件夹的 ZIP 包（自动为 3 级及以下文件夹注入 `README.md`、为 2 级空目录注入 `.gitkeep`、附带一次性 `项目启动.md`），并提供 Agent 开场白一键复制与 WorkBuddy 沙箱下载兜底逃生舱。
- **本期明确不做（Not In Scope / NIS）**：
  1. 不调用任何在线 LLM API，不建立后端服务器或云端账号系统；
  2. 不在 `.antigravityignore` 中强制预写 `reference/`（初始化为空基础文件，由用户后续自主维护）；
  3. 不将原 FDE 中 9 个领域专项技能（本体/OCR/文档解析）和 1 个 Codex 专属技能纳入通用打包池；
  4. `01-需求收集`、`04-产品测试`、`05-产品运维` 本期仅提供轻量可扩展目录骨架，不强塞开发阶段的内循环 Evals/Deliver 技能。

## 3. 核心业务规则与计算逻辑

### 3.1 开发阶段双模式状态机
| 当前勾选阶段组合 | `devModeOverride` | 生效的 `devMode` | 03 阶段打包 Skills 数量 | 03 阶段工作流起点 |
|---| :---: |---| :---: |---|
| 不含 `03` | — | 不适用 | 0 | 仅生成所选非开发阶段目录与模板 |
| 同时含 `02` + `03` | `false`（自动） | **`linked`（精简开发模式）** | **6 个改造版核心技能** | `02` 产物手动交接进 `03/Raw/` → `init_project.py --mode linked`（无 `docs/PRD.md`）→ `product-spec` 直读 `Raw/` |
| 含 `03` 但不含 `02` | `false`（默认） | **`full`（完整开发模式）** | **12 个通用软件工程技能** | 从 `03/Raw/` 客户原始资料起步 → 清洗/看板/原型 → `init_project.py --mode full` → `docs/PRD.md` → `product-spec` |
| 含 `03` 但不含 `02` | `true`（手动开启） | **`linked`（精简开发模式）** | **6 个改造版核心技能** | 适用于后期增量追加 `03` 阶段承接已有 `02` 设计稿的场景 |

### 3.2 目录命名与同级动态重排规则
1. **1 级阶段文件夹**：使用固定两位生命周期前缀 `01`～`05`（防止增量追加阶段时撞号）：
   - `zh`：`02-产品设计阶段`
   - `en`：`02-product-design`
   - `bilingual`：`02-product-design-产品设计阶段`
2. **2 级及以下普通业务文件夹（`numbered: true`）**：
   - 在同一父文件夹下，收集所有 `checked === true` 的子文件夹；
   - 对其中 `numbered === true` 的文件夹，按当前排列顺序从 `1` 开始分配前缀 `1-`、`2-`、`3-`（每级独立从 1 重排，不使用 `1.1-`）：
     - `zh`：`<index>-<nameZh>`（如 `1-业务上下文`）
     - `en`：`<index>-<nameEn>`（如 `1-context`）
     - `bilingual`：`<index>-<nameEn>-<nameZh>`（如 `1-context-业务上下文`）
3. **免序号白名单节点（`numbered: false`）**：
   - 系统配置与工程约定目录（`.agents`、`rules`、`skills`、`.antigravityignore`、`AGENTS.md`、`README.md`、`Raw`、`HANDOFF.md`、`项目启动.md`）在任何语言模式下均保持固定原名，不加序号。

### 3.3 自动生成文件与索引联动规则
1. **1 级阶段 `AGENTS.md` 动态索引**：当用户在树形工作台勾选、取消、重排或新增 2 级目录时，对应阶段 `AGENTS.md` 中的「二级目录导航表」实时同步更新目录名与职责说明。
2. **3 级及以下文件夹自动生成 `README.md`**：在树形勾选界面隐藏 `README.md` 复选框；在预览完整目录树与打包 ZIP 时，为每个 `level >= 3 && kind === 'folder' && checked === true` 的文件夹自动生成一份包含其子文件清单与职责说明的 `README.md`。
3. **2 级空文件夹自动生成 `.gitkeep`**：对于 `level === 2 && kind === 'folder' && checked === true` 且其下无任何已勾选子文件的文件夹（如 `Raw/`、`drafts/`、`reference/`），打包 ZIP 时自动写入 0 字节 `.gitkeep`。

## 4. 异常场景与边界处理
| 异常编号 | 触发场景与条件 | 系统拦截/降级方式 | 用户可见提示文案 | 恢复路径 |
| :---: |---|---|---|---|
| EX-01 | 用户尝试取消勾选最后一个已选阶段 | 禁止取消最后一个阶段复选框 | “至少需要保留 1 个工程阶段” | 先勾选其他阶段再取消当前阶段 |
| EX-02 | 用户尝试取消锁定节点（如阶段 `AGENTS.md` 或 `03/Raw/`） | 锁定复选框置灰不可取消，显示锁形图标 | “核心工作区入口文件，不可移除” | 无需恢复 |
| EX-03 | 用户导入的 JSON 配置文件格式损坏或版本不兼容 | try/catch 拦截并保持当前配置不变 | “配置文件格式无效，请检查是否为本工具导出的 JSON 文件” | 重新选择有效 JSON 文件 |
| EX-04 | WorkBuddy 内置预览器沙箱拦截 `a[download]` 触发 ZIP 下载 | 下载弹窗同时常驻显示「沙箱兜底逃生舱」 | “若在内置预览器中未弹出下载，请点击右上角在系统浏览器打开，或一键复制下方本地初始化脚本” | 点击「复制本地初始化脚本（macOS/Linux .sh）」或「复制项目启动.md」 |
