# 02-五阶段生命周期与双模式规范

## 1. AI 时代软件工程五阶段定义

每个阶段对应现实世界中的一个专业岗位工作区（1 级阶段目录），拥有固定语义编号前缀（`01`～`05`），避免用户后续增量追加阶段时发生序号冲突：

| 阶段固定编号 | 中文名 | 英文名 | 中英双语目录名 | 对应岗位与核心工作 | V1 内置深度 |
| :---: | --- | --- | --- | --- | --- |
| `01` | `01-需求收集阶段` | `01-requirement-collection` | `01-requirement-collection-需求收集阶段` | 售前/商业分析：需求调研、竞品分析、市场分析 | 轻量可扩展骨架 |
| `02` | `02-产品设计阶段` | `02-product-design` | `02-product-design-产品设计阶段` | 产品经理：三层六步上下文、业务/页面 PRD、字段清单、前端原型 | **深度内置**（全套防跑偏约束 + 三大模板 + 提示词） |
| `03` | `03-产品开发阶段` | `03-product-dev` | `03-product-dev-产品开发阶段` | 研发/FDE：技术架构、产品总规格、Feature 拆分、前后端实现与 Evals 验收 | **深度内置**（双模式 FDE 技能包 + 工程规范 + 校验脚本） |
| `04` | `04-产品测试阶段` | `04-product-testing` | `04-product-testing-产品测试阶段` | 独立测试/QA：集成测试计划、压测报告、UAT 验收回归 | 轻量可扩展骨架 |
| `05` | `05-产品运维阶段` | `05-product-ops` | `05-product-ops-产品运维阶段` | 运维/SRE：部署手册、监控告警策略、故障应急与备份预案 | 轻量可扩展骨架 |

*(注：FDE 体系自带的 `project-evals`、`deliver-project`、`maintain-project` 属于开发内循环的“边写边验、验完交付”，固定打包在 `03-产品开发阶段` 内，不拆散到 `04/05`。)*

## 2. 开发阶段双模式判定与技能裁剪规则

当用户勾选包含 `03-产品开发阶段` 时，系统自动根据阶段组合判定开发模式（同时提供手动覆写开关，方便用户后期单独追加 `03` 承接已有 `02` 成果）：

### 模式 A：完整开发模式（Full Dev Mode）
- **触发条件**：勾选了 `03-产品开发阶段`，且**未勾选** `02-产品设计阶段`（且未手动开启“已有上游 PRD/原型”开关）。
- **工作流链路**：从 `Raw/` 原始客户资料出发 → 需求资料准备与清洗 → 痛点需求看板 → 可点击体验原型 → `init_project.py --mode full`（含 `docs/PRD.md`）→ `product-prd` → `product-spec` → `feature-spec-planning` → 开发实现 → `project-evals` → `deliver-project` / `maintain-project`。
- **内置 Skills（12 个通用软件工程技能）**：
  - 核心工程主干（7 个）：`build-fde-project`、`product-prd`、`product-spec`、`feature-spec-planning`、`project-evals`、`maintain-project`、`deliver-project`
  - 需求与原型前置（5 个）：`prepare-requirement-materials`、`normalize-project-requirements`、`review-project-requirements`、`build-frontend-prototype`、`playground`

### 模式 B：【特殊】精简开发模式（Linked Design-to-Dev Mode）
- **触发条件**：同时勾选 `02-产品设计阶段` + `03-产品开发阶段`（或单选 `03` 但手动开启“承接已有 02 设计产物”开关）。
- **跨阶段交接方式**：用户将 `02` 阶段定稿的业务 PRD、页面 Demo PRD、字段清单与原型手动复制进 `03-产品开发阶段/Raw/`，并填写 `Raw/HANDOFF.md` 交接清单。
- **工作流链路**：**彻底跳过需求清洗、需求看板、体验原型与 `docs/PRD.md`** → 运行 `init_project.py --mode linked`（不创建 `docs/PRD.md`）→ 调用改造后的 `product-spec` 直接读取 `../Raw/` 生成 `docs/specs/product-spec.md`（建立 `PSC-NNN` 合同）→ `feature-spec-planning`（直接锚定 `PSC-NNN` 拆解 Feature Map 与三件套）→ 开发实现 → `project-evals` → `deliver-project` / `maintain-project`。
- **内置 Skills（6 个改造版核心工程技能）**：
  - `build-fde-project`、`product-spec`、`feature-spec-planning`、`project-evals`、`maintain-project`、`deliver-project`。
