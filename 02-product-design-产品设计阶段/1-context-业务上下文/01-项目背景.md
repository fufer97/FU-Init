# 01-项目背景

## 1. 核心痛点与立项初衷
在 AI 编程与 AI 产品协作时代，直接用一句话让 Agent 写 PRD 或写代码，往往只能得到空泛模板或偏离业务的代码（**AI 输出质量 ≈ 上下文质量 × 提示词质量**）。
然而，每次开启新项目时，从零手动搭建规范的多阶段目录、编写 `AGENTS.md`、配置 `.agents/rules/` 与 `.agents/skills/`、整理上下文与模板既繁琐又容易遗漏；而现有的单一视角模板（如仅面向 PM 的产品设计目录，或仅面向 FDE 的开发初始化脚本）彼此割裂，缺少从「产品设计」到「产品开发」的无缝衔接。

## 2. 系统定位
**「一键项目初始化（Project Initializer）」** 是一款零大模型调用成本、纯前端驱动的 **AI 项目骨架与上下文/技能包可视化配置及打包工具**：
- 用户在 Web 界面完成「语言、主力 Agent、软件工程阶段、目录树轻编辑与实时预览」后，一键导出标准化的 **ZIP 初始化包**（含各阶段工作区目录、定制化 `AGENTS.md`、内置高质量模板、双模式开发 Skills 及一次性 `项目启动.md` 引导文档）。
- 用户将 ZIP 解压到自己新建的 0 级项目文件夹后，由本地 Agent（如 Antigravity 2.0）读取引导文档，自动接管并对话式补全业务背景或初始化工程代码。

## 3. 目标用户与使用场景
| 角色 | 典型痛点 | 使用本工具的核心收益 |
|---|---|---|
| 独立操盘手 / 一人全栈（如 fufu） | 同时兼顾产品设计与 Agent 驱动开发，手动搭目录与搬运 Skills 耗时且易乱 | 一键勾选 `02-产品设计 + 03-产品开发`，自动启用精简开发模式，打通 02 PRD → 03 `Raw/` → `Product Spec` 闭环 |
| AI 时代产品经理（PM） | 每次新开业务模块都要重搭 `context/template/prd` 与防跑偏 `AGENTS.md` | 一键选择「产品设计专精」预设，开箱获得含 6 大防跑偏约束与三套标准模板的设计工作区 |
| 前线交付工程师（FDE / 开发者） | 原版 FDE 技能包带特定品牌硬编码且 22 个技能混杂，不同项目裁剪麻烦 | 按需获取去品牌化、纯净通用的 12 个完整开发技能或 6 个精简开发技能包 |

## 4. 技术栈与发布约束
- **技术栈**：Vite + React 18 + TypeScript + Tailwind CSS + Lucide Icons + 内联 JSZip + `vite-plugin-singlefile`（纯前端浏览器本地打包，不涉及任何 LLM 调用或后端服务）。
- **发布载体**：适配 **WorkBuddy「资料库 → 发布为网站（`workbuddy.link`）」** 的硬性单文件限制，构建产物为**单个自包含、零外部 CDN 依赖的 `.html` 文件**，同时内置沙箱下载兜底逃生舱。
- **视觉美学**：结合 `unslop` 技能与 **Oil UI `#atlas` 画册编辑风格**（暖纸白 `#FAF9F6`、深墨绿黑 `#17201B`、修长衬线标题 × 等宽编号 × 极简无衬线正文）。
