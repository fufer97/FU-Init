# 03-目录层级与命名排序规则

## 1. 四层目录架构（还原真实岗位工作区）

| 层级 | 定义 | 谁创建 | 规范说明 |
| :---: | --- | --- | --- |
| **0 级** | 项目总目录（如 `XXX项目/`） | 用户手动新建 | 整个项目的顶层容器；导出的 ZIP **顶层不含 0 级文件夹**，直接解压进此目录即可 |
| **1 级** | 阶段 / 岗位维度（如 `02-product-design-产品设计阶段/`） | ZIP 解压生成 | 按岗位隔离；**用户日常用 Antigravity 直接打开 1 级阶段目录作为独立 Workspace** |
| **2 级** | 阶段内功能目录与工作区入口（如 `1-context/`、`Raw/`、`AGENTS.md`、`.agents/`） | ZIP 解压生成 | 位于 1 级工作区根部，保证 `.agents/rules/`、`.agents/skills/`、`.antigravityignore` 被 Agent 自动加载；**2 级文件夹不自动生成 `README.md`**（由 1 级 `AGENTS.md` 直接索引） |
| **3 级及以下** | 具体业务模块子目录与项目文件（如 `4-prd/1-order-采购订单模块/`） | ZIP 解压 / 后续迭代 | 树形界面勾选时隐藏 `README.md`，**打包生成时自动为所有 3 级及以下文件夹生成导航 `README.md`** |

## 2. 三种语言命名规则

支持在 Web 端一键切换三种语言模式，所有普通业务/分类目录实时联动重命名：
- **中文模式**：`<序号>-<中文名>`（如 `1-业务上下文`、`02-产品设计阶段`）
- **英文模式**：`<序号>-<英文kebab名>`（如 `1-context`、`02-product-design`）
- **中文+英文（双语模式）**：**英文在前、连字符连接**，格式为 `<序号>-<英文kebab名>-<中文名>`（如 `1-context-业务上下文`、`02-product-design-产品设计阶段`），兼顾命令行路径安全与中文可读性。

## 3. 序号重排与免序号白名单

1. **普通业务目录每级从 1 重排**：
   - 1 级阶段目录固定使用 `01-`～`05-` 生命周期编号；
   - 2 级、3 级及以下的普通业务文件夹统一使用 `1-`、`2-`、`3-` 连续整数前缀，**每一级文件夹内部独立从 1 重新排序**（严禁使用 `1.1-`、`1.2-`）。
   - 当用户在 Web 第二页取消勾选某目录或上下调整同级顺序时，剩余已勾选的同级业务目录**自动实时重算 `1-`、`2-` 序号**，并同步更新 `AGENTS.md` 与 `README.md` 中的路径引用。
2. **系统 / 工具 / 标准工程目录免序号白名单**：
   - 隐藏目录与配置文件：`.agents/`、`rules/`、`skills/`、`.antigravityignore`、`.gitkeep`、`AGENTS.md`、`README.md`、`项目启动.md`；
   - `03-产品开发阶段` 内部的所有工程约定目录：**`Raw/`**、**`.agents/`**，以及 `init_project.py` 创建的 **`frontend/`**、**`backend/`**、**`docs/`**、**`evals/`** 一律保持标准英文原名且不加序号，确保所有 Skills 与 Python 校验脚本 100% 稳定兼容。

## 4. 空目录防丢失机制（`.gitkeep`）
由于 2 级文件夹不生成 `README.md`，对于打包时内部尚无初始文件的空目录（如 `5-prototypes/`、`6-drafts/`、`7-reference/`、`Raw/`），打包引擎自动静默写入一个 0 字节的 `.gitkeep` 文件（在 Web 树形界面中隐藏），防止 ZIP 解压工具或 Git 提交忽略空目录。
