## 2. 工作规范（三层六步方法论）

- **分层推进**：严格遵循「宏观层（业务上下文 → 系统骨架 → 场景流程）→ 中观层（字段清单 + 业务规则 → 用例推演）→ 微观层（页面实现规格 + 前端原型）」分层设计。
- **单一权威源**：每类事实只在一个权威文件中维护；字段定义以 `项目初始化配置字段清单.md` 为准，跨模块规则以 `1-context-业务上下文/` 为准。
- **格式约定**：所有产出文档统一使用简体中文 Markdown；单个上下文或 PRD 文件控制在 2000 字以内，超长内容按模块或页面拆分。
- **不确定即标注**：遇到未明确的产品规则，必须标注 `【待确认】`，禁止自行脑补假设。

## 3. 六大防跑偏硬约束（改源头，不改对话）

1. **防幻觉**：只使用 `1-context-业务上下文/` 与字段清单中已定义的配置项、阶段和规则，不凭空编造未授权的功能。
2. **防遗忘漂移**：所有确认的规则变更必须写回 `1-context-业务上下文/` 或 `4-prd-需求文档/`，不把口头对话当作持久记忆。
3. **防范围蔓延（NIS 边界）**：
   - Web 配置器 100% 纯前端本地运行，**不调用任何 LLM API、不建后端数据库、不要求配置 API Key**；
   - MVP 深度内置 `02-产品设计` 与 `03-产品开发` 阶段资产，`01/04/05` 阶段仅提供轻量可扩展目录骨架；
   - 主力 Agent 优先适配 **Antigravity 2.0** 与 **通用标准 Agent**；
   - `.antigravityignore` 仅生成空基础文件，不强制预写 `reference/`，由用户初始化后自主维护。
4. **防过度简化**：输出字段清单与配置规则时，不得擅自省略任何枚举值、联动条件或兜底逻辑。
5. **防风格漂移**：前端视觉严格锁定 **Oil UI `#atlas` 画册编辑美学 + `unslop` 去 AI 塑料感规范**（暖纸白 `#FAF9F6`、深墨绿黑 `#17201B`、衬线标题 × 等宽编号 × 无衬线正文，禁止霓虹渐变、发光与装饰性 Emoji）。
6. **防层级混淆**：写业务 PRD 时聚焦状态与规则，写页面 Demo 版 PRD 时聚焦布局、交互与组件承接。
